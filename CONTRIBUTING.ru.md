# Как предложить blueprint

[English](CONTRIBUTING.md) · **Русский**

## Как добавить blueprint

1. Blueprint лежит в **вашем публичном репо на GitHub** с лицензией. Исходники (`blueprint.json`,
   `versions.ts`, иконка) должны быть в репо, а не только в релизе. Начать проще с
   [blueprint-template](https://github.com/KubekPanel/blueprint-template).
2. Опубликуйте **GitHub release** (не pre-release) с одним ассетом `.kbp`. Тег совпадает с версией в
   манифесте: `1.2.0` или `v1.2.0` для `"version": "1.2.0"`.
3. Откройте PR, в котором:
   - файл `community/<id>.json`:
     ```json
     {
       "id": "com.yourname.palworld",
       "repo": "yourname/kubek-palworld"
     }
     ```
     Если `.kbp` в релизе несколько, добавьте `"asset": "palworld.kbp"`.
   - строка в списке **Community** в `README.md` и **От сообщества** в `README.ru.md`, по алфавиту.
     Описание можно оставить на английском в обоих:
     ```md
     - [Palworld](https://github.com/yourname/kubek-palworld) - Palworld dedicated server. Linux, Windows
     ```
4. CI скачает последний релиз и проверит его, код проверяется вручную.

Проверить заранее: `bun install && bun run validate --remote community/<id>.json`.

**Обновления** без PR: просто выпустите новый релиз, тег должен совпадать с версией в манифесте. Индекс
подхватит его в течение 6 часов. Если релиз не прошёл проверки, остаётся предыдущая версия, а предупреждение
видно в workflow Publish index.

## Правила

- `id` в reverse-domain и в нижнем регистре (`com.yourname.game`), одинаковый в манифесте и в имени файла.
  Префикс `com.kubek.` только для официальных.
- В манифесте есть `manifestVersion: 1`, `version` в semver, `name`, `description`, `author.name` и
  `engines.kubek`. Если иконка файлом, то это `.png` внутри пакета. Если сервер работает не везде, укажите `platforms`.
- Серверы скачиваются только из официальных источников игры или её разработчиков, без своих зеркал.
- Не кладите игровые файлы, которые вы не вправе распространять. Если серверу нужны файлы из копии игры
  игрока, опишите в README, где их взять.
- `exec` только когда нет декларативного шага, и в README перечислено, что запускает каждый `exec`.
- Никакой телеметрии, майнеров, скрытых загрузок и работы с файлами вне папки сервера.
- В README описано, что делает blueprint, на каких ОС работает и какие у него ограничения.

Записи, которые нарушают правила, долго не работают или потеряли репо, удаляются. Вредные ещё попадают в
`blocklist.json` с причиной, чтобы панели, где они уже стоят, предупредили пользователей. Нашли проблему?
[Откройте issue](../../issues/new/choose).

## Официальные blueprint'ы

В `official/<name>/` лежат исходники и собранный `.kbp`. При каждом изменении поднимайте `version` и
пересобирайте `.kbp`, `bun run validate` упадёт, если версии пакета и исходников расходятся.
